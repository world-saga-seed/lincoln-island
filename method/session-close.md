# Closing cleanly: sessions, tasks, volumes

A skipped close leaves debris: tasks marked "in progress" that finished weeks ago, runs stopped by a usage limit with their remaining steps carried nowhere, rulings given in conversation and never written down, and notes citing task papers instead of cards. The next session inherits all of it. So every task, wave and session ends by a fixed list, run in order, and a step that cannot be done is written down, never skipped silently. The lists, and accepting a volume, are in [retrospective](../workflows/retrospective.md).

## The rhythm across sessions

Tasks, waves and the "next wave" rhythm are in [tasks-and-waves.md](tasks-and-waves.md).

Things the writer says that move the work along:

| When | Say |
|---|---|
| A discussion has settled some work | "draft the tasks and a wave" |
| The wave is ready | "next wave" (runs every task in it, the retrospective last) |
| The work is good to keep | "commit this" |
| Claude has started before the discussion is done | "stop, we are still discussing" |
| At the end of a session | "close the session" (runs the [session list](../workflows/retrospective.md#closing-a-session)) |
| After a good session | "what did this session do that is worth keeping?" |

When a session runs long, close it and start a new one rather than letting it run on. The new session reads only what the files say, which is the point.
