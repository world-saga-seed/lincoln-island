# Workflows: the procedures

A workflow is a procedure a task cites instead of restating: its loop, its prompts, its checks and its lessons. Copy this whole folder into your book as `plan/workflows/`. When a task develops a method worth keeping, the method comes here and the task cites it; each run's lessons are appended to the workflow's Lessons.

**Rules every workflow follows:** the marks; the ledger first; at most two agents, none spawning another, each with a named file list; no git commands in any agent; fresh agents (not forks) for critics and readers; every finding quotes the text, and the quote is checked; work inside the horizon.

The two largest are **[drafting/](drafting/README.md)**, the drafting and criticism chain, and **[reader-tests](reader-tests.md)**, unit tests for a novel by chapter. Which stage uses which workflow is in the kit's `pipeline/`.

## Belongs here, and does not

- **Belongs:** a reusable procedure (`name.md`), its prompt files (`name/`), and its lessons.
- **Does not:** a run's output (that goes to the task's folder), lore (to the cards), rulings (to the ledger).
